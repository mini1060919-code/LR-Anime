# M5-B 自動測試報告

## 環境與基準

- M5-A 基準：`002529e38d072f39f9af137b14de5206fee5d672`
- Node.js v24.22.1、npm 11.9.0；沿用鎖檔，沒有新增相依套件。
- Chromium／SwiftShader；本雲端以外部 Playwright 設定指定 `/usr/bin/chromium`、單 worker、deviceScaleFactor 0.5。未修改專案預設瀏覽器設定。

## 單元與建置

`npm test`：30 個測試檔、701 項全部通過（原有 657 + M5-B 44）。

`npm run build`：成功；32 張來源 RGBA PNG、四人固定映射與 20 表情、28 張可用素材與 18 預留槽驗證通過。既有單一主 chunk 超過 500 KiB 的建置警告仍存在；不是建置失敗。

新增覆蓋：85/35 疲勞遲滯及 10 秒最低休息、讀檔冷卻續接、手動目標保留及優先返工、不可驅離手動工作者、手動待命、Auto 控制、關閉建築預設 Auto、可工作人數與 HQ 待命人數分離、健康順位、職業／技能／建築優先級、容量／重複／懸空參照、死亡及拆除目標清理、確定性、無額外 XP 或資源、跨版原始來源備份、槽位與 JSON 往返、14 類損壞／未知資料保護。

長期模型測試以 8 人基地運行 30,000 遊戲秒（200 個 150 秒日夜週期等值），使用實際經濟、飢渴與需求計算，每 2 秒自主派工；觀察多次真實休息／返工、容量去重、資源有限且在上限內、無飢渴死亡。此測試不模擬 200 次夜襲；原夜襲由既有單元與瀏覽器日夜回歸驗證。

既有 M4／M5-A 測試快照更新為四個功能標記；舊版 fixture 則移除相應新元件，確保測到真實舊版輸入。原有需求效率測試改用疲勞 84（避免觸發新增的 85 強制休息），仍以健康／士氣為 0 驗證 40% 效率下限，未關閉自主功能來繞過測試。

執行命令：

```sh
npm test
npm run build
E2E_SLOW_WEBGL=1 ./node_modules/.bin/playwright test --config /workspace/.cloud-setup/LR-Anime/playwright.config.mjs
```

專案標準命令仍為 `npm run test:e2e`；上述外部設定僅用於本雲端的系統 Chromium 與軟體 WebGL。已恢復既有 M3／M4／M5-A 回歸產生的歷史截圖，只提交新的 M5-B 畫面。

M5-B 桌面 1000px 與手機 390px 兩案例：實際高疲勞進入休息、手動指定保留但不強迫疲勞者上工、匯入有效休息中快照後由真實需求模擬恢復、優先返工並讓自主者讓位、容量唯一性、黎明保存及重載 UID／工作意向、恢復自主與手動待命、英文切換。該測試加速設定夜晚結束以檢查黎明存讀，原版 smoke 另驗證自然日夜。
