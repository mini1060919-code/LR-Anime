# 整合候選的存檔安全審查

候選固定為 `f2df451b0fccf4c62ac71821817bf130376d18bc`；本次沒有存取使用者日常瀏覽器、玩家上傳 JSON 或真實 localStorage。測試以 Node mock storage 與 Playwright 新建隔離 context 的合成存檔執行。沒有改動遊戲程式或遷移格式。

## 資料生命週期

| 輸入 | 候選處理 | 資料保護 |
| --- | --- | --- |
| v4／v5 | 確定性遷移至 v6，補角色、成長、需求、自主資料 | 原始匯入字串／舊來源永久保留，遷移失敗拒寫 |
| M3 v6 | 保留 runId／UID／素材參照，追加缺少的已知元件 | 不重新生成既有角色 |
| M4 v6 | 保留技能／經驗／職業／工作，補需求及自主預設 | 原來源受保護；不抹除成長 |
| M5-A v6 | 補自主元件，從目前手動建築推導意向 | 原需求／冷卻時鐘等欄位保持 |
| M5-B v6 | 驗證後恢復自主意向、休息、冷卻與所有角色欄位 | 不重設冷卻，不因重新載入重複給 XP |
| 未知版本／未知功能旗標／破損 schema | 拒絕 | 不自動覆寫、清空或默默補成有效新版 |

完整 requiredFeatures 依序為 `characters-v1`、`progression-v1`、`survival-needs-v1`、`autonomy-v1`。外層仍為 v6，各元件有自己的 schemaVersion。已標記新版元件卻缺少欄位時拒絕，不以「舊版預設值」掩蓋損壞。

UID 沿用 runId＋居民 ID；高水位 nextSurvivorId 持續保存，死亡不重用。原生 v6 零人口保持零人口，舊版不明確空人口拒讀，避免自動復活。具名角色保留固定美術及職業參照；派工排序不改職業、能力或肖像。

## 寫入與備份

- 先驗證候選、現有檔與備份清冊，先保存原始資料，再更新 active／slot。localStorage setItem 容量失敗不會部分覆寫該 key；整體多 key 操作不是交易，因此失敗時可能多留一份備份，但不得失去原 active。
- 全域最多三個可輪替普通備份；永久／升級來源與無法辨識的備份不自動輪替。相同來源去重；內容未變的 native checkpoint 不因 reload 消耗備份。
- 三個手動槽、JSON 匯入匯出沿用同一套驗證及保護路徑；即使升級候選已與 active 相同，舊 JSON 來源仍需被永久保護。
- 單存檔 2 MiB 限制，永久備份仍可能累積至容量不足。失敗時提示玩家並保留資料，不會為騰空間刪除永久備份。需由玩家自行匯出與明確管理保留策略。
- 手動槽及 JSON 是最近黎明 checkpoint，並非任意戰鬥瞬間快照；本次不改此語意。多分頁並行沒有跨分頁交易保證，操作存檔時應使用單一遊戲分頁。

## 測試證據與邊界

本次 `npm-test.log` 的 701 項單元案例包含 v4／v5／各 v6 元件補全、遷移輸入不變、未知／損壞資料拒讀、quota 失敗、備份輪替 200 黎明、三槽、JSON 原始來源、死亡及高水位、工作與技能／經驗／肖像保存、自主冷卻續接。

本輪完整 Playwright 16／16 通過，含實際容量不足、原始資料保護與跨版 UI 匯入匯出，原始輸出在 `evidence/playwright.log`；未引用歷史 M5-B PASS 取代本輪測試。測試資料只能證明所涵蓋結構，不能保證尚未提供的每一份真實玩家舊檔；需要驗收特定玩家存檔時，先保全原 JSON，取得明確測試授權後在隔離 context 讀取，不能直接載入日常存檔環境。

舊存檔沒有記錄手動待命意向，無法可靠推導，預設自主；仍在 autoAssign=false 建築工作的居民可推導手動目標。防衛建築同樣會因疲勞釋放工作槽，HQ 待命防衛保持，可能影響遊玩難度，須人工驗收。

## 版本回復與資料回復分開

Git tag／revert 只回復程式。M5-A 或更早程式不認得 autonomy-v1，不能讀取 M5-B 完整存檔；禁止只移除旗標假裝向下相容。回復前先匯出完整新版 JSON、保存原始來源與各槽；由使用者選擇升級前備份，在隔離環境驗證後再決定恢復。v5 相容副本無法保留完整身分、經驗、需求、自主狀態，不能取代新版備份。
