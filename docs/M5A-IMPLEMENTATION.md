# M5-A 居民需求：實作規格

## 基準與範圍

基準為遠端最新 M4 `2d1f408`，分支 `feature/m5a-survival-needs`，PR base 為 `feature/m4-survivor-progression`。M1–M4 功能保留；不修改 main、不合併、不部署。

沿用 M3 runId／數字 ID／UID／外觀 ID、M4 六技能／經驗／工作分配。沒有修改 Three.js 地圖、攝影機、美術、建築定義、射擊／夜襲與原死亡條件。M5-A 不含自主休息／醫療／工作 AI、疾病、叛逃或永久離隊。

需求邏輯位於 `src/needs/`，面板在 `src/ui/needspanel.js`；生產、採集、植林與研究讀取獨立需求效率。M4 經驗仍只來自實際成果，效率下降後自然按較少的成果結算，不憑時間額外授予技能經驗。

## 三個數值

每名存活居民保存 `needs:{fatigue,health,morale}`，全部為 0–100 有限數字，變化後保留六位小數。新居民／舊檔缺省為疲勞 0、健康 100、士氣 70，初始需求效率 100%。

公式使用原遊戲每個白晝 90 遊戲秒作為率的單位；一個完整日夜為 150 秒，不把白晝率誤當整個週期率。

### 疲勞

- 有效值勤：`+18 × 職業係數 / 90` 每遊戲秒。
- 休息：`−30 / 90` 每遊戲秒。
- 值勤須為存活居民，指向仍存在、hp>0、啟用、非缺電且有職缺的建築，workers 名冊亦須反向包含此人。停工、消失或不一致參照不增加工作疲勞。
- 值勤包含在崗維護；倉滿或缺料未產出時，不虛構 XP，但仍可累積值勤疲勞。要休息可用 M4 解除工作／停工；原自動派工仍可能分配另一份工作，沒有新增休息 AI。
- 待命 HQ 民兵只在實際造成傷害的該步視為活動；沒有命中的空轉不加此活動。活動標記在該次需求結算後清除，最高技能者亦正常計活動。

職業係數：斥候／守衛 0.95、後勤 0.97、機械技師 0.98、研究員 1.02，其餘 1；統一限制於 0.95–1.05。職業 ID 與四位具名人物職業不改動。

### 健康

- 飢餓 ≥75：每 90 秒 −8 健康。
- 口渴 ≥75：每 90 秒 −12 健康；同時存在時相加。
- 飢餓、口渴均 <50：每 90 秒 +6 健康；中間區間不恢復也不額外扣除。
- 使用原有進食／飲水處理後的實際需求值，不再扣一份食水。診所仍透過 M4 原有減緩飢渴間接保護健康，不新增疾病與醫療 AI。
- 健康 0 不新增死亡；原飢餓／口渴達死亡條件、建築被摧毀的居民死亡與 HQ 淪陷仍維持原規則，健康不能用來擋下原本應發生的死亡。

### 士氣

以目標值 `T` 而非每幀任意累加：從 70 起算，依條件加入以下項目，再 clamp 至 0–100：

| 條件 | 目標調整 |
| --- | --- |
| 休息 | +8 |
| 有至少一份食物且飢餓 <50 | +5 |
| 食物不足一份 | −10 |
| 有至少一份水且口渴 <50 | +5 |
| 飲水不足一份 | −15 |
| 飢餓 ≥75／口渴 ≥75 | −15／−20 |
| 健康 <40 | −15 |
| 疲勞 ≥75 | −10 |

個性目標偏移：樂觀 +4、堅定 +2、耐心／好奇 +1、謹慎 −2、內斂／體貼 −1、務實 0；合計限制 ±5。這是獨立規則表，不改 M4 原有個性學習係數，也不賦予離隊或其他 AI 行為。

士氣每 90 秒最多向 T 移動 12 點，不能超越目標。食物、飲水、健康與休息影響可逐項測試，不引入亂數或牆鐘。

## 工作效率

只減少，不給額外正產量：

```text
F = 1 − 0.25 × clamp((疲勞−40)/60, 0, 1)
H = 1 − 0.50 × clamp((70−健康)/70, 0, 1)
M = 1 − 0.10 × clamp((40−士氣)/40, 0, 1)
個人需求效率 = clamp(F×H×M, 0.40, 1.00)
建築需求效率 = 有效工作參與者的個人需求效率平均值
```

疲勞超過 40、健康低於 70、士氣低於 40 才逐步扣效率，避免輕微變化立即大幅改平衡；最差仍保留 40%，不造成零產出死鎖。值勤居民自身需求只結算一次，即使同一人有多種工作成果或駐軍射擊。

倍率作用於食物／加工／發電、採集、植林進度與研究，仍受原資源上限及 M4 有限技能倍率約束。無人力建築不虛構居民需求倍率。HUD／建築產量預估亦讀取同一倍率。戰鬥傷害、診所／廣播／車庫等既有支援光環不調整，避免本階段同時重做整套戰鬥與光環平衡；UI 有明確說明適用範圍。

可獨立關閉需求效率：需求仍按實際模擬步更新，但工作效率恢復 M4 數值。M4 技能加成開關維持獨立，不把兩個系統混在一個旗標。

## 時間與存檔

需求集中於一次正時間步的戰鬥後、日夜轉換及黎明保存前更新。主迴圈提供獨立遞增步號，讀檔從保存的 lastStep 繼續；日夜切換歸零 timeInPhase 不會重扣或讓需求時鐘倒退。

拒絕重複／倒退／非整數步號，以及非有限、≤0 或 >1 秒的 dt；現有主迴圈最高時間步在此範圍內。跳過步號不代表補算離線時間，暫停、低幀率與牆鐘變化不直接產生額外結算。elapsedSeconds 僅累計有效遊戲 dt，保留九位小數；沒有待處理活動佇列跨讀檔重播。

存檔沿用 v6，新增 versioned survival 元件與必要功能標記，詳見 [相容性](M5A-SAVE-COMPATIBILITY.md)。新增居民用安全預設，死者不更新／復活，UID 高水位不變。

## UI 與已知範圍

原動漫全身立繪、頭像、五表情、六技能、經驗與 M4 派工都保留。新增三條有方向意義的 meter、繁中／英文狀態、需求效率及開關。狀態門檻與數值分開，健康「良好」表示 ≥70，不表示數值必為 100。

本版是有限的需求／計算／顯示系統。沒有自動班表；長期全天值勤會累積疲勞，需要玩家利用既有派工控制安排休息。健康壓力率與效率寬限門檻刻意溫和，保留原快速飢渴死亡規則；長局平衡仍需驗收。
