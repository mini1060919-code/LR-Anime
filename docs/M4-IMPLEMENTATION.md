# M4 居民能力與成長：實作規格

## 基準與分支

2026-11-17 檢查遠端最新分支：M1 `feature/save-protection-v5`=`642c8d2`；M2 `feature/m2-zh-tw-anime-ui`=`e89c3a7`；M3 `feature/m3-anime-art-integration`=`14ddcdd`。M1→M2 為 22 檔前端／語系整合；M2→M3 為 80 檔人物、v6、素材與測試。M4 直接由 M3 建立 `feature/m4-survivor-progression`，PR base 為 M3，不合併、不部署。

沿用 M3 runId、數字居民 ID、UID、高水位、職業／個性 ID、外觀 ID、generator 與全部美術。沒有修改 Three.js 地圖、攝影機、建築定義或圖片。戰鬥模組僅插入有限能力倍率與實際命中結算，沒有改射擊目標選擇或視覺系統。自動工作分配維持原本排序，不加入 M5 AI。

## 能力與實際工作

`src/progression/rules.js` 管理成長規則；`work.js` 處理參與者、有限倍率與一次性結算；`assignments.js` 提供核心派工命令；`schema.js` 管理附加資料與驗證。UI 僅呼叫驗證命令。

| 能力 | 經驗來源（只計實際完成量） | 能力效果上限 |
| --- | --- | --- |
| agriculture 農業 | 農場、菜園、溫室、牧場實際入庫食物：1 XP/單位；植林站完成一棵樹：1 XP | 相應食物產量 +10% |
| engineering 工程 | 冶煉／蒸餾實際入庫產物、有效發電輸出、研究點：1 XP/單位 | 加工、發電及研究產出 +10% |
| medicine 醫療 | 已套用診所照護倍率、實際避免的飢餓／口渴增量：1 XP/10 點 | 原診所減耗倍率再乘最低 0.97；0.85→0.8245 |
| scavenging 探索採集 | 真正交付的伐木／拾荒／採礦資源，獵人／漁屋食物：1 XP/單位 | 相應產量 +10% |
| defense 防禦 | 砲塔、駐軍及 HQ 民兵真正扣除的殭屍 HP：1 XP/10 HP | 原傷害 +10%，不改射程、射速或目標 |
| logistics 後勤 | 有燃料且有人工作的車庫支援已交付採集量：1 XP/4 單位；廣播站支援成功抵達的新居民：1 XP/人 | 車庫支援採集額外 +5%，只取一座有效車庫 |

生產加成為 `1 + 0.02 × 有效參與者平均等級`，最多 1.1；後勤倍率取其一半增幅，最多 1.05。採集者與後勤合計最多 `1.1×1.05=1.155`，不按居民／車庫數量無限疊加。原有科技、天氣、建築升級、資源容量與既有光環規則保留。資源已滿、無原料／燃料、無節點、停工、零 dt、無命中目標，不憑時間給經驗。發電只計可儲存或供負載使用的量，滿倉且無負載不給經驗；不為自動發電的無工作建築建立虛構參與者。

原診所只有飢渴減耗，沒有傷病；本次依此計照護工作，不新增疾病、士氣或疲勞。原維修沒有指定居民，本次不給無法歸屬的維修經驗。後勤車庫缺油時原有光環的歷史規則不改，但不提供 M4 額外搬運加成或經驗。多診所／車庫／廣播站採最低建築 ID 的有效支援者，避免同一成果重複分配。

## 等級與職業個性

`abilityRanks` 仍為 0–5。經驗以整數 milli-XP 保存，1000=1 XP；累計門檻為 0、10、30、60、100、150 XP。最高 150 XP／5 級，不無限累加。UI 顯示到下一級的區間進度；已有高等級的舊檔，經驗預設為該等級最低門檻，不降級或重新抽取身分。

完成量按實際參與者平均分攤，套用獨立學習係數：相應職業 +10%，個性按規則表 +2%（堅定）或相應領域 +3%，總增幅最多 +15%。職業對應：農務員→農業、機械技師／研究員→工程、醫護→醫療、斥候→採集、守衛→防禦、後勤→後勤；通才沒有專項加速。個性只影響相應學習效率，不改飢渴、士氣或 AI。規則表列出所有既有個性，可擴充而不在核心 tick 散落角色姓名判斷。四名具名人物的職業不變，也沒有改職業操作。

不足一個 milli-XP 的餘數保存在 `experienceRemainders`，範圍 [0,1)，以 12 位小數保留。相同有效工作量、人物規則與事件序列可重現；不使用牆鐘、隨機數或浮動 UI 刷新給經驗。原遊戲仍以 dt 積分，升級跨界後的產出會受下一個 tick 的新等級影響，不宣稱不同巨大時間步下所有經濟數值逐位相同。

每份完成收據綁定目前 state、原 UID、建築與參與者；發出後立即同步結算，使用後作廢。偽造、複製、重複、跨 state 或讀檔後重播均不接受；沒有待處理經驗佇列跨存檔重播。保存單調遞增的 sequence，避免重設結算高水位。這是內部完成工作 API，不是讓 UI／外部輸入任意授予經驗的公共命令。

駐軍最多四人、HQ 民兵最多六人，依存活居民 ID 選定實際槍手；無參與者、死亡者及超出槍數者不分經驗。過量傷害只按實際失去的 HP 計算。名冊同步仍刪除死亡者的 active profile，保留唯一原型保留表與居民高水位。

## 派工與 UI

- 面板保留全身圖、頭像、五表情、姓名、職業、個性、背景與現有工作；新增六個技能／經驗進度與繁中／英文介面。
- `assignResident` 以居民與建築 ID 驗證存活、建築存在、hp、啟用狀態及工作容量，檢查成功才移除舊職位並寫入新職位；失敗保留原工作。所有職業均可參與既有工作，專長只影響學習效率。缺電可預先派工，但無實際生產便無產出經驗。
- 指派使目的建築進入原有手動模式；解除工作使原建築保持手動，避免立刻自動派回。可按「恢復建築自動派工」，也保留原勞動面板與自動分配。
- UI 沒有直接寫 workers／buildingId；只有核心命令修改。開啟面板沿用原暫停行為，不在面板中自動長經驗。可切換「有上限的能力加成」，停用時仍記實際工作經驗，但資源與戰鬥回到原數值。資源預估與建築檢視已納入倍率。
- 存檔仍是既有黎明檢查點；派工與經驗在下一次黎明保存。手動槽複製最近檢查點，不新增即時戰鬥存檔。
