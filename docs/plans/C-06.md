# C-06｜一次性結算與存檔安全 v0.1

企劃及隔離原型交付。正式資料遷移、遊戲寫入、UI 與整合驗收待辦。

## 寫入與回復契約

正式工程沿用 startDay 這個唯一權威來源與既有黎明結算。先捕捉前日資料，將既有黎明更新和 C 報告快照放入同一候選 checkpoint。若已提交同一 run 與 day，讀回已提交值，跳過整段可重入結算。B-04 僅接收提交後可查詢的鍵。畫面、載入、事件重播與換語言均走唯讀查詢。

驗證既有存檔及來源世代後，以單筆原子儲存提交新 checkpoint、已結算識別與日報。正式方案須證明併發排他或 compare-and-swap，再實作跨分頁支援。寫入失敗不得發出已提交通知，保留上一個 checkpoint 及其備份。在可重試的候選或恢復原 checkpoint 後重試，禁止在已突變的記憶體狀態再跑黎明。重試前重讀持久化資料，處理寫入成功後通知失敗的情況。舊版讀取及匯入沿用既有遷移，不補造日報。未知版本或必要功能原檔保留且拒絕一般覆寫。

## 驗收矩陣

| 案例 | 所需證據 |
|---|---|
| C06-01 首次黎明、重複通知、重載 | 同一 run/day 只提交一次日報。比對招募、聲望、庫存、死亡計數及 ID。 |
| C06-02 B-04、跨日重播、切換語言 | 原日報 ID、快照與證據不變，結算與寫入增加零次。缺日報保持待查看。 |
| C06-03 失敗與並行 | 注入 quota、寫入前後中斷、雙分頁同時寫入、較舊 checkpoint。驗證原始備份位元組、只一個成功版本及可重試狀態。 |
| C06-04 v4/v5/v6、未來版、損壞或缺必要功能 | 用合成樣本經現有真實讀取／匯入／自動儲存路徑驗證。舊檔原始備份和角色／建築關聯保留，未來版自動與手動路徑均拒一般覆寫。 |
| C06-05 ID 與歷史 | 比較 reload、slot 切換、重複匯入與多 run 的角色、建築、日報及結構化事件鍵。現行事件無持久 ID，新增契約與遷移須先設計；不得由本地化事件文字推導。 |
| C06-06 全套與 UI | 正式整合候選執行 npm ci、npm test、npm run build、Playwright 單 worker 零重試且失敗留 trace。兩語與 1000px／390px 確認焦點、地圖及既有操作。 |

## 已執行的原型測試
