# A～E 階段紀錄規則
各工作包獨立保留完整編號、交付物、證據及風險：[A](A.md) · [B](B.md) · [C](C.md) · [D](D.md) · [E](E.md)。

## 狀態字典（每項均須明確標示）
- **規劃中**：有需求或提案，未具可驗收交付物。
- **設計產出待核對**：先前對話可能完成，但尚未驗證原檔、版本及使用權利。
- **已開發待驗證**：程式／素材存在但缺完整測試。
- **驗收通過**：有具體版本、測試與審查證據。
- **已整合**：合併進指定整合分支且相容驗證通過。
- **已發布**：正式發行且有發布證據。
上述狀態不可跳級；若無證據，一律維持待核對。

## 每次更新請填
- 日期（時區 Asia/Taipei）、工作包及子項、版號、責任線、狀態。
- 需求／變更內容、輸出檔案／GitHub Commit／PR、素材來源授權、測試紀錄。
- 存檔與向下相容影響、尚存缺口、下一個工作編號。
- 於 [變更日誌](../CHANGELOG-PLAN.md) 留一筆可追蹤紀錄。
- 文件更新使用獨立 PR 審查；不得未經驗收就改寫成「完成」。
