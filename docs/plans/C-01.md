`src/game/phase-controller.js:startDay` 是既有夜→日入口，調整日序、天氣、聲望、招募並自動儲存。草案於它清除敵人或重設 deathsToday 以前取前日資料，於既有黎明變更完成後採樣資源與人口，與該次 checkpoint 一起提交。新遊戲 day 1 尚未度過一夜，顯示歷史空白。Three.js 晨光、載入事件、B-04、語言及畫面互動均為唯讀或與結算無關。

日報鍵為 `(run.id, dawnDay)`，ID 提案為 `JSON.stringify([run.id,dawnDay])`。已驗證的 v6 run.id 來自 persistence；v4/v5 沿用既有遷移生成的身分。快照保存 schemaVersion、dawnDay、reportId 與資料層級缺值；禁止以 slot、語言、日期時間或 seed 代替身分。回載同一黎明會讀既有 ID；同一 run 的舊 checkpoint 回溯後重新到達已有黎明，保留首份已提交日報。分岔是否要產生新 run 需另審。

v6 envelope 使用 exactKeys 與 requiredFeatures；正式落地須單獨評估版本化 envelope 和回復相容，沿用未知版拒寫與原檔備份。避免把 C 欄位附加在現行 v6 或用兩次無交易保障的寫入。C-06 規格定義寫失敗與競爭處理。
